# Prompt for cfo.ai (Ari)

Attach `drivers.csv` and `inputs.json` from this folder, then paste the prompt below. Both files are generated by `droid-monkey econ` from droid-monkey's own runs.

```text
droid-monkey is an AI agent for Android teams. It runs on an emulator in CI, attacks the app with real-world faults (process death, rotation, network loss, low memory, revoked permissions), and fixes the crashes and lost state it finds with the developer's consent. Every fix is verified by replaying the same attack, and droid-monkey opens a PR with the evidence. Customers are Android teams at app companies; it sells as a GitHub CI add-on.

Use the attached drivers.csv for every cost. Rows with measured=yes come from droid-monkey's run receipts (the same costs are on its neatlogs traces), and the source column names the run. Keep that source on each Variable. Rows with measured=no are assumptions; label them as assumptions.

Unit costs: attacks cost no model spend, only CI compute (compute_per_run). Spend comes from fix attempts: cost_per_fix_attempt_mean, with p90 for bad months. Expected fix attempts per run = expected_fix_attempts_per_run. Each new repo has a one-time setup cost (code analysis + UX audit, about $1.4 to $4.9; use the setup_cost and ux_audit_cost rows).

Plans: Free at $0 (10 attack-only runs a month, no fixes), Team at $99 per repo per month (30 runs, fixes within team_fix_budget_per_run), Scale at $499 per repo per month (300 runs, fixes within scale_fix_budget_per_run), plus $3 per verified fix above a plan's budget (price_per_verified_fix). Add Stripe at 2.9% plus $0.30 per paid invoice, $25 fixed costs a month and no founder salary. Start with $5,000 cash on 2026-11-01 and model 18 months.

Customers: Base adds 10 Free repos a month, 1 Team repo a month in months 2 to 6 and 2 a month after that, and 1 Scale repo in months 9, 12, 15 and 18. Growth adds 30 Free, 3 Team a month and 1 Scale a month from month 4. Monthly churn is 10% Free, 5% Team and 3% Scale.

Make these Scenarios and compare them with Base on gross margin per plan, month-18 MRR, month-18 cash and runway:
1. "Bad release month": every fix attempt costs cost_per_fix_attempt_p90 and twice as many attacks break.
2. "No budget cap": runs fix every failure (fix_attempt_share = 1) with no fix budget.
3. "Scale repriced": Scale at the price that keeps a 70% gross margin at expected cost.
4. "Usage pricing": no fixes included in Team or Scale; every verified fix is billed at $3.

Report the gross margin per plan in each Scenario, and the month cash goes negative, if it does.
```
